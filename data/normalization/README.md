# Train-only normalization reports

This directory contains lightweight audit, parameter, and summary products
generated by:

```text
notebooks/04_train_only_normalization.ipynb
```

The files document the normalization applied to Landsat-derived annual LST and
spectral-index products before T3 tensor construction and model training.

## Purpose

The normalization workflow is designed to:

- place predictor and target variables on numerically stable scales;
- preserve a common scaling across training, validation, and test periods;
- prevent validation and test statistics from influencing model preparation;
- retain the parameters required for inverse transformation of LST predictions
  to degrees Celsius;
- provide an auditable record of input geometry, file availability, masks, and
  normalized value ranges.

## Train-only parameterization

### LST target

Annual LST is standardized using a global z-score:

```text
LST_z = (LST - mu_train) / sigma_train
```

The parameters `mu_train` and `sigma_train` are estimated only from valid LST
observations belonging to the training target years:

```text
2016-2019
```

The same parameters are applied without recalibration to validation and test
targets.

### Spectral predictors

The six annual spectral indices are normalized using robust train-only
percentile limits:

```text
NDVI, NDMI, NDBI, UI, SAVI, BSI
```

For each index, the lower and upper limits correspond to:

```text
p2.5 and p97.5
```

Under the T3 formulation, the training targets 2016-2019 use antecedent
predictors from:

```text
2013-2018
```

Therefore, spectral normalization parameters are estimated only from those
training predictor years and then applied unchanged to all later inputs.

Climate-radiative descriptor normalization is handled in the NASA POWER
integration workflow documented in Notebook 05 and is not the principal scope of
this directory.

## Included files

### Geometry and input checks

- `04_input_v6_geometry_audit_2013_2025.csv`  
  Audit of raster dimensions, spatial reference, affine transform, extent, and
  geometric consistency for the annual input products.

- `04_normalized_products_file_existence_2013_2025.csv`  
  Verification of the expected normalized annual products and identification of
  missing or unavailable files.

### Normalization parameters

- `04_normalization_parameters_train_only_2013_2025.csv`
- `04_normalization_parameters_train_only_2013_2025.json`  
  Frozen train-only parameters used for LST standardization and spectral-index
  scaling.

The `2013_2025` suffix identifies the full operational product period covered by
the audit. It does not mean that validation or test years were used to estimate
the normalization parameters.

### Value and mask audits

- `04_normalization_audit_values_2013_2025.csv`  
  Summary statistics and range checks for original and normalized products.

- `04_train_spatial_mask_summary_2013_2025.csv`  
  Summary of the spatial mask used to restrict parameter estimation to valid
  training-domain pixels.

### Workflow summaries

- `04_train_only_normalization_summary_2013_2025.csv`
- `04_train_only_normalization_summary_2013_2025.json`  
  Compact records of the normalization workflow, retained variables, temporal
  scope, and generated outputs.

- `04_normalization_figures_manifest_2013_2025.csv`  
  Manifest of the diagnostic normalization figures associated with Notebook 04.

## Naming note

The identifier `v6` in:

```text
04_input_v6_geometry_audit_2013_2025.csv
```

is a historical processing-version label retained for traceability. It should not
be interpreted as a distinct modeling experiment or public model version.

## Interpretation limits

The files in this directory document preprocessing and leakage-control decisions.
They do not contain:

- training, validation, or test patches;
- model predictions;
- model checkpoints;
- full-resolution normalized rasters;
- evidence of model performance;
- independent validation results.

The audit tables support verification of the normalization logic but do not
replace the full-resolution inputs used during tensor and patch construction.

## Storage policy

This directory is restricted to lightweight CSV and JSON products.

The following items are intentionally excluded:

- original and normalized full-resolution GeoTIFFs;
- aligned raster stacks;
- tensor archives;
- patch datasets;
- trained model weights and checkpoints;
- full-resolution prediction and residual maps;
- temporary processing products.
